# Baseline and guard demonstration: issue 32

Everything here was measured on
`fiat/32-back-to-markets-lender-markets-page`, cut from `main` at
`a17f0fa6fece61b3c118c8995d1bfce47d77ce09`, before any file in the step was
changed.

## Environment

Node 22.22.1 and npm 11.12.0, matching `engines`. Dependencies installed with:

```bash
PUPPETEER_SKIP_DOWNLOAD=true npm ci
```

The skip is required. A plain `npm ci` fails in the puppeteer postinstall,
because the local browser cache holds the version directory without the
executable inside it. Puppeteer serves HTML and PDF rendering in the API
routes and is reached by nothing in the jest suite.

## Jest needs NEXT_PUBLIC_TOKENS_IMG_HOSTNAME to produce any output

`next.config.mjs` reads `images.remotePatterns[0].hostname` from that
variable. This repository carries no dotfiles at all, `.env` included, so it
is unset, the hostname is `undefined`, and Next rejects the configuration.
`next/jest` then hands jest a configuration under which it collects zero
tests and prints nothing: no summary, no `--listTests` output, not even
`--showConfig`. It exits 1 under `--ci` and 0 without it, so an unset run
reads as an empty pass.

Worked to cause rather than assumed. A minimal inline jest config
(`-c '{"testEnvironment":"jsdom","rootDir":"."}'`) listed all 30 suites, which
put the fault in the `next/jest` configuration chain rather than in jest or in
the tree. Setting the variable to `raw.githubusercontent.com`, a hostname the
same config file already lists literally, restores normal output.

Every jest command in this delivery sets it.

## Pre-change type check

```bash
npx tsc --noEmit
```

The answer depends on one untracked file. `tsconfig.json` includes
`next-env.d.ts`, which declares the image module types and is generated by
Next's own tooling rather than committed. On a tree where it has not been
generated, tsc exits 2 with five `TS2307 Cannot find module` errors:

```text
src/app/[locale]/layout-style.ts(1,19): '@/assets/pictures/overviewBG.webp'
src/components/@extended/MarketStatusChip/index.tsx(6,18): '@/assets/icons/fire_icon.png'
src/components/LeadBanner/index.tsx(4,19): '@/assets/pictures/bannerBG.webp'
src/components/NetworkIcon/index.tsx(4,26): '@/assets/pictures/ethereum-icon.webp'
src/components/NetworkIcon/index.tsx(5,24): '@/assets/pictures/plasma-icon.png'
```

Once the file exists, the same command exits 0. Both states were observed on
unchanged trees in this delivery.

The first recorded version of this file said four errors. That was read off a
truncated view of the output and is corrected here; the study and the runbook
carry dated amendments saying the same thing. The step's gate now asserts that
no type error names a file the step changed, which holds in both states,
rather than pinning a count that moves with whether a generated file happens
to be present.

## Two checks that cannot run here

`npm run lint:errors` drops into `next lint`'s interactive "How would you like
to configure ESLint?" prompt and exits 1, because there is no `.eslintrc`.

`npm run build` was already recorded by pull request 13 as exiting 1 on a
different API route each run, with a control build on the unchanged tree
failing the same way.

Neither is used as an exit condition. Both are worth someone's attention on
their own account.

## Guard demonstration

The new suite was written before the component changed and run against the
component as it stood.

Before, `npx jest src/components/BackButton`:

```text
Tests:       1 failed, 3 passed, 4 total

  ● BackButton > gives the lender market sidebar a link to the markets page

    Unable to find an accessible element with the role "link" and name
    `/Back To Markets/i`

    Here are the accessible roles:

      button:

      Name "Back To Markets":
```

Three cases pass before the change because they exercise the link path
`BackButton` already took for its other seven call sites. Exactly one fails,
and it fails on the reported control being a button rather than a link to
`/lender`. That is the defect in issue 32 and nothing else.

After the change, the same command:

```text
Test Suites: 1 passed, 1 total
Tests:       4 passed, 4 total
```
